# RETRO.md - Task 3A: Retrospective

## 1. Plan Mode value

Amending the plan in PLAN_LOG.md session 2 (PATCH /tasks/{id}) prevented a problem that would have needed a revert one session later. Claude's plan wrote `test_update_task_priority_valid` as `update_task_priority(1, 2)`, which permanently changes seed task 1 from priority 3 to priority 2 in the shared in-memory `TASKS` dict in repositories/tasks.py. tests/test_tasks.py has no fixture that resets `TASKS`, so every priority-filter test I added in session 3 (`test_list_tasks_filtered_by_priority`, `test_list_tasks_filter_excludes_other_priorities`) would have run against corrupted seed data, and I would have had to go back and rewrite a session 2 test, which CLAUDE.md's "do not edit or delete existing tests" rule forbids once it is committed. My amendment ("test_update_task_priority_valid must create its own task with create_task ... tests must not change seed tasks 1-3") closed that off before any code was written. The same session's amendment 4 swapped `data["priority"]` for `data.get("priority")` in routes/api.py, which turned a raw KeyError (500) into a ValidationError (422) before it shipped.

## 2. Plan Mode limits

The one case where output did not match the amended plan was PLAN_LOG.md session 3 (GET /tasks?priority={n}). The approved plan said `test_list_tasks_all` would check that no filter "returns every task currently in TASKS (assert via ID membership/count)", but Claude wrote `assert {1, 2, 3}.issubset(result_ids)`, which only checks the three seed tasks, and it named the priority-5 task "High priority task" and the priority-1 task "Low priority task", the reverse of the spec (1 = urgent, 5 = low). All three of my explicit amendments in that session were followed exactly; the divergence happened in the one test the plan described in loose prose rather than as code. That tells me Plan Mode is reliable for the parts of a plan that are concrete (file names, function names, exact asserts) and unreliable for anything left as a description, so approving a plan does not replace reading the diff. It also does not carry across sessions: a manual `flask run` + curl check that I removed in session 1 reappeared in sessions 2 and 3, because each amendment lived only in that session's plan and not in CLAUDE.md.

## 3. Subagent value

The most important boundary to enforce was the one between services/users.py (SA-2) and routes/api.py (SA-3): SA-2 owns the `email`/`sms`/`none` check and the NotFoundError in `update_notification_pref`, and SA-3 was told "Do not touch services/users.py ... Do not import anything from repositories/". Because of that split, the three routes SA-3 added are one-line calls into services/, and every rule about valid values lives in one tested place (tests/test_users.py, 9 tests). When Claude implements a feature in one session it does not keep that line: in Week 5 Drill 1 Phase 1 (due_date, single session, no Plan Mode) it edited repositories/tasks.py, services/tasks.py, routes/api.py and tests/test_tasks.py in one pass and its tests reached into `task_repo.TASKS` directly, and in PLAN_LOG.md session 1 it put request-parsing branches for `priority` inside `create_task_route`. A single session would also have hidden the gap the pipeline exposed: running `pytest -q` after SA-1, SA-2 and SA-3 returned the same `20 passed` each time, which showed me that the new service functions had no tests until SA-4 and that the new routes are still untested.

## 4. Gap analysis

The constraint I would most want enforced mechanically is SA-2's "Do not touch ... any file in tests/" (with "Do not write tests; SA-4 writes them"), because it is the one where CLAUDE.md itself pushes Claude the other way ("every new service function gets a test in tests/test_<module>.py"); Claude obeyed it this time with no comment, but nothing guaranteed that. A PreToolUse hook on Edit and Write would read the current subagent's allowed output list (for SA-2, only services/users.py) and exit with code 2 and the message "SA-2 may only modify services/users.py; tests belong to SA-4" whenever the target path is outside that list, such as tests/test_users.py.
